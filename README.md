# Транзакционная память — MAUI приложение (Лабораторная работа)

Полноценное .NET MAUI приложение, демонстрирующее механизмы транзакционной памяти (STM) и визуализацию параллелизма.

## 📱 Что реализовано

Проект реализует **оба примера из задания**:

### Пример 1 — Симуляция STM через CAS (`Interlocked.CompareExchange`)
- Файл: `Models/CasAccount.cs`
- Классический пример из методички: безопасное пополнение баланса без `lock`
- Алгоритм:
  1. Чтение текущего состояния ("начало транзакции")
  2. Локальное вычисление нового значения
  3. Попытка фиксации через `CompareExchange` — если `_balance` не изменился, фиксируем
  4. При конфликте — откат и `retry` (цикл `while`)
- Визуализация: N потоков (кружки вокруг счёта), цвет = состояние (чтение/вычисление/конфликт/коммит), счётчик конфликтов CAS

### Пример 2 — "Настоящий" учебный STM-движок (MVCC)
- Файлы: `Models/TVar.cs`, `Models/StmEngine.cs`
- Аналог `Nito.Transactions` / `TxContext.ExecuteInTransaction`, которого нет в официальном .NET (MSR STM.NET закрыт)
- Подход **MVCC** (Multi-Version Concurrency Control), как в Clojure STM:
  - `TVar<T>` хранит `(Value, Version)` атомарно одной ссылкой
  - `Read()` — снимок на момент начала транзакции (изоляция)
  - `StmEngine.Transfer` — валидация версий + коммит под короткой блокировкой
  - При конфликте версий — откат и повтор
- Визуализация: параллельный перевод денег между счетами A и B, сумма A+B сохраняется (инвариант), конфликтные транзакции мигают красным и перезапускаются

Всё обёрнуто в **MVVM** (`ViewModels/MainViewModel.cs`), с анимированной графикой на `GraphicsView` (`Views/StmDrawable.cs`), логом событий и настройками.

## 🚀 Запуск

### Требования
- .NET 8 SDK
- MAUI workload: `dotnet workload install maui`

### Команды

```bash
# Клонировать
git clone <repo>
cd TransactionalMemoryMAUI

# Восстановить и запустить (выберите платформу)
dotnet build -t:Run -f net8.0-android
dotnet build -t:Run -f net8.0-windows10.0.19041.0
dotnet build -t:Run -f net8.0-maccatalyst
dotnet build -t:Run -f net8.0-ios

# Или просто
dotnet build
```

### Как пользоваться
1. Выберите демонстрацию в Picker:
   - **Демо 1: CAS** — N потоков пополняют один счёт
   - **Демо 2: STM-перевод** — N потоков переводят A↔B
2. Настройте слайдерами:
   - Количество потоков (2-60)
   - Сумму депозита / перевода
3. Нажмите **"Запустить"** — увидите:
   - Анимированные кружки-потоки (цвет = состояние)
   - Линии к счетам
   - Счётчики конфликтов (retry)
   - Лог событий
4. **"Сброс"** — очищает состояние

## 🧠 Связь с теорией (для пояснительной записки)

| Пункт теории | Где реализовано |
|---|---|
| Оптимистичный подход (vs pessimistic lock) | `CasAccount.Deposit` и `StmEngine.Transfer` — нет lock на время работы, только короткая блокировка на фазе commit |
| Чтение снимка / изоляция | `TVar<T>.Read()` возвращает снимок `(Value, Version)` |
| Валидация и коммит | `StmEngine.Transfer`: проверка версий перед записью |
| Откат и Retry при конфликте | `while(true) + onConflict callback` — возврат к чтению заново |
| MVCC (как в Clojure STM) | `TVar<T>` хранит версию вместе со значением |
| CAS (Compare-And-Swap) | `Interlocked.CompareExchange` в `CasAccount` — прямой аналог примера 1 из методички |
| Сохранение инварианта при параллелизме | Демо 2: сумма A+B остаётся постоянной (1500) при любом количестве параллельных потоков |
| Невозможность deadlock | В STM нет взаимных блокировок — только retry |
| Проблема побочных эффектов | В комментарии к `StmEngine` — I/O нельзя откатить |

Подробнее см. `Task/Tranzaktsionnaya_Pamyat.pdf` и `Task/Laboratornaya_Rabota_1.pdf`.

## 🎨 Визуализация

- **GraphicsView** + `IDrawable` (`StmDrawable`)
- Потоки = кружки вокруг счёта (Демо 1) или между счетами (Демо 2)
- Цвета:
  - Серый — ожидание
  - Голубой — чтение снимка
  - Оранжевый — вычисление
  - Красный — конфликт / Retry
  - Зелёный — коммит (успех)
- Анимация: лёгкое вращение / покачивание активных потоков, таймер 80мс
- Легенда внизу графики

## 📚 Использованные подходы

- **CAS**: самый близкий аналог STM в .NET из коробки для простых типов
- **MVCC**: учебная реализация, как в Clojure, Haskell (TVar), Scala (Ref)
- **TL2-подобный commit**: глобальный `CommitLock` только на фазе валидации (в реальных STM — global clock)
- **MVVM**: `INotifyPropertyChanged`, `ICommand`, data binding

## 🔍 Проверка корректности

- Демо 1: при N=100, amount=10 итог всегда 1000 (без потерь)
- Демо 2: сумма A+B всегда 1500, несмотря на параллельные переводы в обе стороны
- Конфликты логируются и считаются — видно, что retry работает

## 📝 Примечания

- Официальной STM в .NET нет (MSR STM.NET закрыт). Используются:
  - `Interlocked` для CAS (из коробки)
  - Кастомный `TVar` + `StmEngine` для учебного STM
  - В продакшене: `ConcurrentDictionary`, акторы (`Akka.NET`), каналы (`System.Threading.Channels`), Event Sourcing / Sagas
- В транзакции нельзя делать неоткатываемые действия (Email, файл) — это ограничение STM, упомянутое в методичке
